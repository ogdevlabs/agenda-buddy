ADR-032. One member on the shared interface: Task<TEntity?> FindOneAndUpdateAsync(BsonDocument filter, BsonDocument update). Post-image (ReturnDocument.After) so the incremented failure counter comes back with the write; IsUpsert left false so AC-9 is a property of the primitive rather than of each call site.
Blast radius measured before writing anything, the same sweep F-016 ran across its 19 changed symbols: exactly TWO implementers, both updated here — MongoDbRepository<TEntity> and Identity.Tests/Helpers/InMemoryRepository.cs. Six Library.Tests service tests use Mock<IRepository<T>> and are unaffected by an added member.
MUST LAND FIRST, and not for tidiness: PRD requirement 4 exists because AC-2 ("a fault between the read and the write") was UNEXPRESSIBLE as a test (11-testing.md:65), and that is how a delete-then-insert survived with 20 passing tests around it. The double gains FaultBetweenMatchAndWrite, invoked after the filter matches and before any mutation.
The double is deliberately strict — an operator or field it does not implement THROWS. A double that silently skipped a filter clause would report green for a query MongoDB would have answered differently, which is worse than having no coverage.
Also: it returns a SNAPSHOT, not the live stored object. Found by its own red test — two successive post-images compared equal, which is the opposite of what the post-image guarantee is for.
