Two new fields on CredentialEntity: failed_attempts (int, [BsonIgnoreIfDefault]) and lock_until (DateTime?, [BsonIgnoreIfNull]). No migration: an absent failed_attempts reads as 0 and $inc on a missing field creates it at 1 — asserted against real Mongo rather than cited.
D-9 ordering: the lock is checked BEFORE BCrypt.Verify, or a locked account costs 262 ms per attempt and the lock amplifies the denial of service it sits beside. Provable because the counter is written only on the verify-failed path, so a locked attempt leaving the counter untouched shows the short circuit fired.
All three refusals — unknown email, wrong password, locked — raise the same exception with the same message. A distinct code or body for "locked" tells an attacker which addresses exist and which they have managed to lock, undoing the enumeration mitigation T-005 added.
The success path is ONE write, not two: the refresh-token rotation login already performed now also carries $set failed_attempts: 0 and $unset lock_until, which is better than the PRD's "at most one extra write".
AC-7's assertion had to change shape at build time: the 401 body is NOT empty, because UseStatusCodePages turns a bodyless 401 into ProblemDetails — the same surprise F-016 hit with its central 403. Asserted as identical bodies after stripping the per-request requestId.
