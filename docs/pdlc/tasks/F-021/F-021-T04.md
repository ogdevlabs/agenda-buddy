ADR-034. Requirement 17 collides head-on with a pre-existing test — IdentityService_ConstructorParameters_ContainNoILogger asserted BY REFLECTION that IdentityService had no logger at all, a structural proxy for "no credential material in logs" from a time when nothing in Identity logged anything. Deleted, and replaced by the stronger content assertion it was standing in for. F-021's ONE deviation from "delete no pre-existing test"; needs maintainer acknowledgement, as F-016's ADR-025 deletion did.
Discovered while wiring it: the three sanitization tests beside it were VACUOUS. They iterated GetMessages(Information) on a logger factory connected to nothing, so they asserted over an empty list and could not have failed. They now run against real output, with Assert.NotEmpty so they cannot silently return to vacuity — which is exactly how the first one went red.
Account identity is logged as acct_ + 12 hex characters of SHA-256, not truncation: PiiRedactingProcessor redacts SPANS, NOT LOGS, so nothing downstream would catch an address written here, and F-013's telemetry rollout is this project's own precedent (threat T-004 — real customer emails exported in url.path the moment telemetry was switched on). "aud…@example.com" still identifies a person in a user base this size. The honest claim is "not an address", not "anonymous".
Operations: credential.created / .login-ok / .login-failed / .locked / .reset / .rotated / .session-ended. The login-ok record carries must-reset {flag} (unenforced — F-022), which is requirement 19's seam and nothing more.
