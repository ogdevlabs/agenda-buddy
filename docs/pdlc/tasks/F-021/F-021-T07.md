verification.md attests all 16 ACs, records the red run, and names eleven things this feature does NOT claim — including that no integration test drives register → login → refresh end to end (all three mint tokens, and CryptoSessionFixture deliberately never materialises a private key as a string in a PUBLIC repository), and that HSTS is inert until F-017 terminates TLS somewhere.
ADR-032 (the primitive), ADR-033 (configuration-gated controls plus the AppHost marker, and why the redirect is not gated), ADR-034 (replacing the no-logger reflection guard). ADR-011 — "no rate limiting on /auth/login in v1" — marked SUPERSEDED, with a note on how its re-evaluation trigger ("if any auth anomaly is detected in logs") could never have fired, because Identity had no log sink until this feature added one.
Context catalog updated where this feature made it false: 13-security.md's rate-limiting and refresh claims, 11-testing.md:65's fault-injection claim.
Two beads filed rather than fixed: the missing unique index on credentials.email (agenda-buddy-b0w) and the limiter's single-bucket behaviour behind a proxy that does not forward the client address (agenda-buddy-end).
Also fixed in passing, because F-021's new test class exposed it: TelemetryPiiTest.RedactionPreservesThePathShape took the FIRST non-empty url.path from a process-wide exporter, which passed only while it was the sole class in that assembly starting a server. It now selects by http.route. Confirmed stable over five consecutive runs.
