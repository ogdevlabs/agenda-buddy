ARCHITECTURE §4: one policy plus seven one-line call sites, and the design says so rather than implying a single edit. Middleware order is a property of each Program.cs — AddServiceDefaults() runs on the BUILDER, before a pipeline exists, so it cannot reposition anything.
Reordering does not fix what it appears to fix, which is why HSTS is in scope: by the time any middleware runs, the password or bearer token has ALREADY crossed the wire. Redirection protects nothing already sent; HSTS is what stops the client repeating the mistake.
UseHttpsRedirection is NOT flag-gated (ADR-033, amending §4's "under their flags"): six services already called it unconditionally, so a flag defaulting to off would silently remove an existing control and one defaulting to on would be decorative. It is a no-op wherever no HTTPS port is known — which is why the whole integration suite and every local HTTP run are unaffected, asserted by TheReorderedRedirectDoesNotBreakOrdinaryHttpRequests rather than assumed.
Identity's if (!IsDevelopment()) guard around its redirect is REMOVED: under the AppHost that condition was always true, so it never meant what it looked like it meant.
AC-12 is a source-text assertion, and the task body says why: IApplicationBuilder exposes no ordered list of registered middleware, and by the time anything can inspect the pipeline it is a composed delegate. The alternatives were seven containers or nothing. The no-direct-UseHttpsRedirection case closes the likeliest regression — not someone moving a line, but someone adding one.
