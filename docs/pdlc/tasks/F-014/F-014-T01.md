Four repositories and four collection names that did not exist: notes and payments in Booking, messages and notifications in Customer, plus IReportingService in Provider (which needs no repository of its own — part of why nobody noticed it was never registered).
MongoDB creates a collection on first write, so there is no migration and no provisioning step. All four names resolve through MongoConnectionResolver.ResolveSetting, so every legacy configuration shape keeps working exactly as the existing five do.
The two pre-existing repository-count tests (F-013) were updated rather than deleted: their intent is "the count and lifetimes are what we expect", and F-014 legitimately changes the count. The lifetime half is the load-bearing assertion and is untouched.
