verification.md attests every AC, records what the live run found, and names what this feature does not claim.
Requirement 20 / ADR D-9: the booking path's read-append-REPLACE became a single atomic $push. Two concurrent bookings for one provider both read, both appended, and the second replacement silently discarded the first appointment — which then existed in the appointments collection and not in the provider document, and ReportingService counts from the embedded copy, so the lost booking was the one that vanished from the dashboard. Asserted on write SHAPE, because the effect is identical under no concurrency and the shape is the point.
Also fixed in passing: TelemetryPiiTest.ExportedSpan_IdentifiesTheEndpointByRouteTemplate was flaky at roughly one run in three. OpenTelemetry's ASP.NET instrumentation is process-wide, and two TracerProviders alive at once do not reliably each receive every activity. This assembly had one server-starting class for years; F-014 added a second and the overlap became real. Fixed with an xUnit collection that disables parallelism — the same mechanism F-016 used for the harness. Six consecutive green runs.
