ADR D-6. There is no Stripe account, no key and no deployment (ADR-035 defers cloud until every pending feature ships), so the two obvious options both fail: a gateway that throws leaves PaymentService unreachable — the exact condition F-014 exists to end — and a gateway that charges by default is unthinkable without an account.
RecordingPaymentGateway records locally and contacts nothing. It REPORTS SUCCESS, which is the risk, so the signal lives in the stored data rather than only in a log: intent ids are prefixed `local_`, which Stripe cannot produce (its ids begin `pi_`). A payment recorded this way is permanently identifiable as one that moved no money.
Threat T-206, and two ways this project has already been burned: a committed secret is permanent (ISSUE-002), and StripePaymentGateway used to assign StripeConfiguration.ApiKey — a PROCESS-GLOBAL STATIC — inside request handling, which makes the key's lifetime the process's and the assignment a data race. It is now assigned once at construction, and the key is an Aspire secret parameter exactly as the JWT keys are.
Residual, accepted (PRD R4): payments could stay permanently fake. Mitigated as ADR-033 mitigated the same shape — a loud startup warning naming the key, outside a local run.
