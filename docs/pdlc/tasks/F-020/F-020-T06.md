PRD Requirements 17/18/20, Known Risks. ARCHITECTURE.md §10. Rename `MobileApp/` → `AgendaBuddy.MobileApp/`,
`MobileApp.Tests/` → `AgendaBuddy.MobileApp.Tests/`: folder, `.csproj`, solution entry, every `namespace
MobileApp.X;` declaration across the whole client (Routing/, Infrastructure/, Services/, ViewModels/, etc.
— this is the largest single-project namespace surface in the rename batch). `MobileApp.csproj` references
`Library.csproj` directly — update to `AgendaBuddy.Library.csproj` (depends on F-020-T01). Update
`AgendaBuddy.IntegrationTests`'s `ProjectReference` to `MobileApp.csproj` (used by
`MobileClientRouteResolutionTest`) and any `MobileApp.X` `using` there.

**This is the highest-risk single rename in the batch** (PRD Known Risks): `MobileApp` is excluded from
`agenda-buddy-backend.slnf` (ADR-031) but not from `agenda-buddy.sln`, has its own Android/iOS TFMs, and is
covered by 3 dedicated CI jobs (`build-android`, `build-ios`, `build-mobile-tests`) that a backend-only
build would never exercise. **Do not verify this task against the slnf alone.** Verify with: `dotnet build
agenda-buddy.sln` (full solution), `dotnet test AgendaBuddy.MobileApp.Tests/AgendaBuddy.MobileApp.Tests.csproj
/p:MobileWorkloads=false` (158 passing / 7 skipped, unchanged), and — if feasible in this environment —
`scripts/run-ios.sh` or the `InstallAndroidDependencies` build target to confirm the mobile-specific TFMs
still resolve under the new folder name. AC 14/15/16.
