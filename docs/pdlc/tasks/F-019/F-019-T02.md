ARCHITECTURE.md §9. **Corrected at the Wave 1 kickoff standup (2026-08-26) — verified against real code, the original premise was wrong:** annotations are mixed, not uniform. `AppointmentEntity` (bound directly as the request body for the 3 original routes) carries `[EmailAddress]` only, no `[Required]`. The 7 F-014 request records (`AppointmentStatusRequest`, `NoteRequest`, `PaymentRequest` in `Booking/Requests/AppointmentExtrasRequests.cs`) carry **zero** annotations. So this spike covers two distinct cases, not one: (a) whether Validot can derive from `AppointmentEntity`'s partial annotations, and (b) authoring Validot rules from scratch for the three annotation-less records — the harder, more open-ended half. Confirm whether Validot rules are hand-written per DTO (likely, per Validot's declarative-rules model) or can be derived from existing annotations where they exist. Produces the actual rule-authoring pattern T05/T06 build against — do not let those tasks guess at Validot's API shape, and do not let them assume every DTO already has annotations to lean on.
