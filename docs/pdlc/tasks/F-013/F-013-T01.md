Resolve OQ-3/A-5 empirically BEFORE any other code. Determine the current Aspire SDK/workload version for .NET 10, the exact integration package names, and whether the MongoDB integration is compatible with MongoDB.Driver 2.25.0 (pinned; source of 3 CVE pins in Directory.Build.props:18-28). DECISION GATE: if incompatible, adopt the escape hatch (plain AddSingleton<IMongoClient> + custom MongoHealthCheck) and do NOT upgrade the driver in this feature. Record the outcome in the episode and update ARCHITECTURE.md section 3.4 + section 8. Also confirm whether CI runners need an Aspire workload install.

## Outcome (2026-08-17)

**DECISION GATE → ESCAPE HATCH TAKEN.** `Aspire.MongoDB.Driver` is excluded. `MongoDB.Driver` stays at 2.25.0 and the 3 CVE pins in `Directory.Build.props:18-28` remain load-bearing.

Environment: SDK **10.0.400**. Aspire stable line **13.4.6**.

| # | Question | Finding | Evidence |
|---|---|---|---|
| 1 | Aspire version / workload | **13.4.6**; **no workload exists or is needed**. Aspire is NuGet-only since 9.0. | `dotnet workload search aspire` → empty; `dotnet workload list` → none installed; AppHost probe built on a bare SDK |
| 2 | Exact package names | AppHost: `Aspire.AppHost.Sdk` 13.4.6 (SDK ref) + `Aspire.Hosting.AppHost`, `Aspire.Hosting.MongoDB`, `Aspire.Hosting.Kafka` 13.4.6. ServiceDefaults: `Microsoft.Extensions.Http.Resilience` / `Microsoft.Extensions.ServiceDiscovery` 10.9.0 + 5× `OpenTelemetry.*` 1.17.0 | nuget flat-container index + successful probe restore |
