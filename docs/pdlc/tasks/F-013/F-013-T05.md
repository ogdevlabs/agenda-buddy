## Standup amendments (Wave 2 kickoff, 2026-08-17)

- **The design claim this task was written against was wrong.** Replacing `MongoDbConfiguration`'s primary ctor with `(IMongoClient)` breaks the compile of `Booking.Tests/Configuration/MongoDbConfigurationTest.cs:17`, `Customer.Tests/Configurations/MongoDbConfigurationTest.cs:17`, `Profession.Tests/Configurations/MongoDbConfigurationTest.cs:17`, which AC-5.2 forbids. **Add the `IMongoClient` ctor; keep the `IConfiguration` ctor with its `GetSection("MongoDB")["ConnectionString"]` body verbatim.** Do not route the legacy ctor through `MongoConnectionResolver` — those mocks stub only `GetSection`, so the resolver's indexer lookups return null and it throws. See ARCHITECTURE.md 3.3.
- **`Profession` is not mechanical.** `Profession/Extensions/ServiceCollectionExtensions.cs:24` runs `SeedDataAsync(database, configuration).Wait()` at DI-registration time, where no `IServiceProvider` exists once the client is a lazily-resolved singleton. Relocate to a hosted service (preferred) or an awaited post-`builder.Build()` call in `Profession/Program.cs`. Budget design time for this.
- No `AddMongoDBClient` — T-01 settled the escape hatch. Use `AddSingleton<IMongoClient>(_ => new MongoClient(MongoConnectionResolver.Resolve(config)))`.
