Discovered while verifying AC-4.1 in T-10. Six of seven services throw at startup in the Development environment: 'Cannot consume scoped service IEventStore from singleton IRequestCollection'. RequestCollection is registered AddSingleton while IEventStore is AddScoped - a captive dependency. DI validation (ValidateOnBuild/ValidateScopes) is enabled only in Development, which is exactly the environment Aspire runs services in, so this blocks AC-1.1 (one command starts successfully) and AC-1.3 (all 7 Healthy). Pre-existing on main, unchanged by F-013, and almost certainly the concrete reason the solution could not be started. Fix: register IRequestCollection as Scoped in the six services that register it. Staging is unaffected because validation is off there, which is why AC-4.1 passed.
