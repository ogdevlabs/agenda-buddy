New files under Library/ (NOT Library/Services/ - AC-5.3). MongoConnectionResolver.Resolve(IConfiguration) tries in order: ConnectionStrings:mongodb, MongoDbSettings:ConnectionString, MongoDB:ConnectionString, LibrarySettings:MongoDB:ConnectionString; throws InvalidOperationException naming every key tried when none resolves - never returns null. ResolveSetting() for collection/database names with the same discipline. MongoHealthCheck issues db.adminCommand ping via injected IMongoClient, and caches its result for 2-5s per threat-model T-002. AC-2.5, AC-4.2, AC-3.2.

## Standup amendments (Wave 2 kickoff, 2026-08-17)

- `ResolveSetting(IConfiguration, string name, string @default)` — argument order fixed; `name` is per-call (Identity uses `MongoDbSettings:CollectionName`, others use per-entity names like `ProvidersCollection`); returns `@default` rather than throwing. Only `Resolve` throws. See ARCHITECTURE.md 3.3.
- `MongoHealthCheck` caching is now specified in ARCHITECTURE.md 3.5: 5s window, registered singleton, injected `TimeProvider` (no static field, no wall-clock reads), cached unhealthy results must also expire.
- **T-03 owns** the `Library.Tests` unit tests for `Resolve` (including the named-key exception message) and for the cache (assert one `RunCommandAsync` across two in-window probes via call-count, never by sleeping). T-04 owns the per-service tests only. This removes the duplicate claim between T-03 and T-04.
