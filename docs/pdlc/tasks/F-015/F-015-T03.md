Builds the route/cluster config programmatically from Aspire service-discovery keys (`services__<name>__http__0`) per the approach F-015-T02's spike confirmed — not a static YARP cluster file, which could drift from what `AppHostWiring.cs` actually wires. One route per service, matching `api/v1/{service}/**`, including `api/v1/auth/**` and the root-mapped `/device-token` → identity. No path rewriting.
Threat T-302 (threat-model.md, mitigate now): the route table must be an explicit allowlist, never a catch-all forward — this is the task that makes ARCHITECTURE.md §2's design decision real rather than aspirational, and the [security] AC above is what the build TDD gate demands a failing-first test for (issue #55).
