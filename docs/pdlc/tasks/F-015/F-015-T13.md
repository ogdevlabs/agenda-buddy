`./scripts/generate-openapi.sh` hasn't been re-run since F-014 added nine new routes — the largest single-feature spec drift this project has recorded (per F-014's episode). This is the feature that will actually read those specs while writing F-015-T07's route corrections, so regenerating them here (rather than deferring again) means Construction works from an accurate reference instead of a stale one.
Independent of every other task — no dependency, can run in Wave 1 alongside F-015-T01 and F-015-T06.

**Closed 2026-08-23.** Ran `./scripts/generate-openapi.sh` (all seven services, so the route index stays complete) with `export PATH="$HOME/.rd/bin:$PATH"` first. The script required no fixes — it ran clean against a throwaway Mongo container and RSA keypair. Only `docs/api/openapi/Booking.json`, `docs/api/openapi/Customer.json`, `docs/api/openapi/Provider.json`, and `docs/api/openapi/index.md` changed; Calendar, Services, Profession, and Identity specs were unaffected. F-014's new routes now appear: Booking gained appointment notes (`GET`/`POST .../notes`, `PUT`/`DELETE /booking/notes/{id}`), appointment payment (`GET`/`POST .../payment`), and the appointment-status transition route (`POST .../status`); Customer gained messages (`GET`/`POST /messages`, `GET /messages/thread/{counterpartEmail}`, `POST /messages/{id}/read`) and notifications (`GET /notifications`, `POST /notifications/{id}/read`); Provider gained deactivation (`POST /providers/{email}/deactivate`) and the provider report (`GET /providers/{email}/report`).
