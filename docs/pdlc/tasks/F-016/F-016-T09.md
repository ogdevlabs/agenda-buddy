Security AC for threat T-001 (HIGH). PRD requirement 18, REASSIGNED from F-021 into F-016 (ADR-028) because this feature is what makes the hole reachable.
OwnershipGuard.cs:9-10 compares with string.Equals(sub, entityEmail, OrdinalIgnoreCase) and does NOT guard against a null claim - so string.Equals(null, null) is true and the guard PASSES. AssertOwnerAny explicitly checks sub is null first (:17); AssertOwner does not. The asymmetry is documented in the repo's own catalog, and the repo is public.
Why it must be fixed HERE, not in F-021: the response-shape projection (task T11) selects owner-vs-non-owner using this exact primitive, and the bypass lands on the OWNER branch - which returns the unprojected ProviderEntity including the full appointment book and subscribed-customer list. The hole exists today but is unreachable at these routes because nothing there branches on ownership. Found by Neo-to-Phantom cross-talk at the threat party; neither the architecture doc nor the PRD surfaced it alone.
