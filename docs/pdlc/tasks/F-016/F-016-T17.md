Security AC for threat T-007. Implements ADR-025. SUPERSEDES PRD requirement 13, which asked for a role check here.
There is NO ROLE TO CHECK FOR. Identity's allow-list is exactly {Provider, Customer} (Identity/Program.cs:100-106) - there is no administrative tier. Bolt found this by going to implement requirement 13. The only implementable check, AssertRole(user, "Provider"), would still let any self-registered provider write to global reference data read by every user; with open unthrottled registration that raises the bar from 'any account' to 'any account that picked Provider at signup'.
Professions are SEEDED from Library/Data/ProfessionSeedData.cs and no shipped flow creates one. Delete the route, its handler wiring, and its RequestCollection/EventsHelper write path. After this, POST /api/v1/professions returns 404/405.
AC-18: the two profession READ routes MUST remain anonymous and unchanged - verify with a test. Leave AddProfessionCommand/AddProfessionCommandHandler in place rather than deleting them; the refactor program will audit dead handlers systematically. If professions ever need to be user-creatable, that is a feature with a real authorization model - not a route quietly restored.
