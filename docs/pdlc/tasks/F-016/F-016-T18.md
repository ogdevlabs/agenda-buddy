AC-17 (BROADENED - see below) and security AC for threat T-005. Requirement 16. Implements ADR-027.
PART 1 - stop the amplification. GetProvidersQueryHandler.cs:23 serialises the ENTIRE provider list - every provider, every embedded appointment, every customer email - into a Mongo document on every call, into a collection that is unbounded, unindexed and never pruned. Reduce query-handler Data to operation metadata with NO entity fields. CONSTITUTION section 3 mandates the audit pattern ('do not remove this pattern') - it is PRESERVED: every handler still writes a success/fail event with status, type and timestamp. Only the payload is reduced.
SCOPE BROADENED AT DESIGN: the PRD names GetProvidersQueryHandler as 'the specific offender', but ALL TEN query handlers follow the identical publish-query-audit shape (docs/pdlc/context/15-cqrs-and-messaging.md:160) and GetCustomersQuery serialises every customer record - an equivalent hole. Implement across all ten. PRD AC-17 tests only the provider path; flagged at the Plan gate to be broadened.
COMMAND handlers are LEFT ALONE (11 of them): they serialise the entity the caller just submitted, so it is not an amplification vector and it is the real audit content for a write.
PART 2 - add Event.actor. A nullable [BsonElement("actor")] string populated from the caller's sub claim. Without it, reducing the payload makes the audit trail LESS useful for incident response than the PII dump was: 'a GetProvidersQuery succeeded at 14:03' with no actor and no correlation id cannot answer a provider asking who saw my client list. Until F-016 these endpoints had no authenticated caller to record - this feature is the first point at which the value exists. Nullable and additive, so NO backfill migration; a backfill is impossible anyway since the actor for a historical anonymous read is genuinely unknown. Cost accepted knowingly (Friday's dissent): this makes F-016 no longer schema-change-free, so its revert leaves harmless unread residue rather than no trace.
