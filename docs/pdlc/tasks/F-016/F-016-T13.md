AC-10 and security AC for threat T-006. Requirement 11. Calendar/Program.cs:93 and :121 call RequireAuthorization() but never OwnershipGuard - a valid token proves the caller is somebody, not that {email} is theirs, so ANY registered user can read ANY provider's full appointment list including customer emails. Its sibling services all guard (Provider:182, Customer:133, Services:122,146); Calendar is the one family that forgot.
DESIGN INVARIANT - THE GUARD MUST EXECUTE BEFORE THE CACHE READ. Both routes cache under $"availability-{email}" / $"appointments-{email}" (:101, :129) - keyed on the request SUBJECT, never the CALLER. Today that is safe by accident (no guard means every authenticated caller is entitled to every entry). Adding the guard keeps it safe ONLY because the guard runs first. Anyone who later reorders, extracts a helper, or caches the RESPONSE instead of the DATA creates a cross-tenant leak - and F-019/F-020 will rewrite these exact files.
T-006 requires a TEST, not a comment: warm the cache as the owner, then request the same {email} as a different authenticated principal, and assert no appointment data comes back. CRITICAL assertion detail from Bolt: assert 'NOT 200 with data', not 'exactly 403' - CacheAside has no test at all and returns default! on a 500ms lock timeout, which surfaces as a spurious 404, so a strict 403 assertion will flake and Build will chase phantom failures.
