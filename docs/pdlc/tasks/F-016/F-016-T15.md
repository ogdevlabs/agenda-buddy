AC-15, AC-16. Requirement 15. Implements ADR-023's endpoint half. Request: ?page=<1-based, default 1>&pageSize=<default 25>. Response envelope: { items, totalCount, page, pageSize }. MaxPageSize = 100.
CLAMP, NEVER REJECT. pageSize=100000 returns 200 with 100 items and pageSize:100 in the envelope. A 400 would tell an attacker the exact boundary and leave an honest client no way to discover the cap; clamping plus echoing the EFFECTIVE value lets a correct client paginate and lets nobody probe. THE CAP IS A SECURITY CONTROL, not ergonomics - an uncapped pageSize restores exactly the full-dataset dump this feature exists to remove.
RETIRE the 204: both endpoints currently return 204 for an empty collection; with an envelope, return 200 with items:[] and totalCount:0 so a client always gets a parseable body. That is a contract change beyond what requirement 15 literally asks for, and it is recorded in ADR-023.
AC-16 requires the response shape recorded as an ADR BEFORE this task closes - ADR-023 is already written, so verify it matches what was built. F-015 writes the mobile client against this shape; it is a contract, not an implementation detail.
