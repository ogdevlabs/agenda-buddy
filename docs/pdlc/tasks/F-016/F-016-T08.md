AC-13, AC-14, and security AC for threat T-004. Implements ADR-022 / ARCHITECTURE AD-1. REQUIREMENT 14 CANNOT BE MET AS THE PRD SCOPED IT: in all seven services UseExceptionHandler is registered INSIDE if (app.Environment.IsDevelopment()) alongside Swagger (docs/pdlc/context/10-error-handling.md:9-34), so a mapping added there gives 403 in Development and a bare empty-bodied 500 in Production.
Implement IExceptionHandler in Library.ServerAuth (the .NET 8+ idiomatic form - used NOWHERE else in this codebase yet, so this introduces the pattern). Register with AddExceptionHandler<T>() plus app.UseExceptionHandler() OUTSIDE the Development guard, in the SIX domain services. Return false for every non-ForbiddenException so the existing Development-only lambda keeps handling what it handles today - the two coexist.
T-004: the body MUST carry status, title and requestId ONLY. No exception type, no message, no stack frame, in ANY environment. Today Production emits an empty 500, which is accidentally the most conservative behaviour possible; this change starts emitting bodies where none existed, so it is an egress change.
The 8 existing hand-written try/catch (ForbiddenException) sites must keep returning exactly one 403 - no double-handling, no changed body. DO NOT register in Identity: it uses an incompatible ad-hoc {error,message} envelope and is the only service without ProblemDetailsServiceEndpointFilter. DO NOT map the other nine exception types (ArgumentException, KeyNotFoundException, FormatException etc) - deliberate YAGNI, each changes an untouched endpoint's contract.
