AC-4, AC-5, and security AC for threat T-002 (CRITICAL). From F-018 T08. Starts a real service and issues real HTTP requests against a MongoDB Testcontainer. CONTAINER PER CLASS with a unique database per test - not per test: F-018's spike MEASURED 4.45s warm startup against the 1-3s assumed, which reversed the original per-test design (ADR-017). The Rancher VM is 2 CPUs / 4.1 GB and already runs a k8s cluster; if it thrashes the mitigation is FEWER, LARGER test classes, not abandoning containers.
THE FAIL-CLOSED GUARD IS THE LOAD-BEARING SAFETY PROPERTY. It MUST assert container IDENTITY, not hostname shape: compare the resolved connection string against the endpoint the Testcontainers API reports for the container this fixture started. A localhost/127.0.0.1 pattern check is EXPLICITLY INSUFFICIENT - Pulse broke that version at the threat party, because reaching Atlas via kubectl port-forward or an SSH tunnel also presents as localhost, and a developer may legitimately run Mongo there. Also refuse anything containing mongodb+srv:// or credential components as a cheap second layer. Abort during FIXTURE CONSTRUCTION, before any test body runs and before any database or collection is created. Why this severity: the repo is PUBLIC and a valid Atlas credential is still recoverable from git history (ISSUE-002, unrotated), and the cluster has NO BACKUPS.
