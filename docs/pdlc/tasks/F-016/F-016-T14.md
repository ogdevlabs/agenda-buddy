AC-11. Requirement 12. Provider/Program.cs:100-129 currently has NEITHER a role check nor an ownership guard, so any authenticated Customer can create a provider record for an arbitrary email.
BOTH ARMS ARE REQUIRED: AssertRole(user, "Provider") AND an assertion that providerEntity.Email is the caller's own sub. A role check alone still lets one Provider create a record for another provider's email. This is one of only TWO AssertRole call sites in the entire solution after this feature - AssertRole has never been called anywhere (docs/pdlc/context/13-security.md:137), so the role claim currently authorizes nothing.
Expect this to SURFACE latent breakage rather than cause it: SeedAuthCredentials is dead code, so any pre-auth provider/customer record has no credential and cannot authenticate at all. That is expected, not feared. Pre-existing oddity to leave alone: a duplicate email returns 400 with a Kafka error string, because KafkaClient reports an already-existing topic as a failure.
