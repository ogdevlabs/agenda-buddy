title: Overlap check against a provider's existing appointments
status: done

Added `BookingService.FindOverlappingAppointmentsAsync(emailProvider, start, end)` — a `FindAllAsync`
query filtering `email_provider` plus the standard half-open interval-overlap predicate
(`existing.start < newEnd && existing.end > newStart`). `BookingAppointmentCommandHandler` calls it
before the provider lookup and fails the command if it returns anything.

Concurrency decision (accepted race, not an atomic conditional write or slot-key index): see
`docs/pdlc/design/booking-correctness/ARCHITECTURE.md` §3.

**Tests:** `BookingServiceTest.FindOverlappingAppointmentsAsync_*` (unit, mocked repository);
`BookingCorrectnessTest.PostAppointments_OverlapsAnExistingAppointmentForTheSameProvider_Returns400`
and `..._ImmediatelyAdjacentToAnExistingAppointment_Returns201` (integration, real Mongo).
