AC-4, AC-12, AC-13b. Threats T-001 and T-004 (both mitigate now). THE central fixture.
CONTAINER PER TEST CLASS, not per test (ADR-017). Reversed from container-per-test on MEASURED evidence: warm Mongo startup is 4.45s (4436/4471/4475 ms, sigma ~20ms), 2-3x the 1-3s assumed at Discover. One WebApplicationFactory per class follows, since the connection string is then known once.
AC-13b: isolation preserved by a UNIQUE DATABASE NAME PER TEST inside the shared container. This is what made the reversal safe - it delivers the same isolation container-per-test was chosen for, at effectively zero cost. Demonstrate with two tests in one class writing the same document id without collision.
AC-4: inject the connection string as ConnectionStrings:mongodb (the key MongoConnectionResolver checks first) with ZERO changes to production source.
FAIL CLOSED (T-001/T-004): MUST ignore ambient environment values and MUST assert the resolved endpoint is the Testcontainer's mapped host/port before any test executes. Developers export ConnectionStrings__mongodb by hand for standalone runs (see DEPLOYMENTS.md gotchas); combined with unique-database-per-test, a misresolution would litter a live no-backup cluster with junk databases.
AC-12: pin every image by explicit tag (e.g. mongo:7.0.14). No :latest.
