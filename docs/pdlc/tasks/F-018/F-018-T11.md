AC-5. One test per service asserting a real HTTP request through the real pipeline returns the expected status.
CRITICAL DESIGN CONSTRAINT (Progressive Thinking Conflict B): assert STATUS CODES, deliberately NOT response envelopes. F-019 introduces DataResponse<T>, which changes every envelope by design. Asserting envelopes now produces tests that must be rewritten in F-019 and cannot distinguish 'F-019 broke behaviour' from 'F-019 changed the shape as intended'.
Caveat to carry: this assumes F-019 preserves status codes. If F-019 changes e.g. Created -> Ok with an envelope, these break too - but that break is then a deliberate, visible contract change, which is the outcome we want.
