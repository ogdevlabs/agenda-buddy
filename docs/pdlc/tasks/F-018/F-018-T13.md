**AC-15 claim narrowed 2026-08-26 at Party Review (Neo's N1, Echo's E1, linked findings — same root cause).**
`EventStoreWriteGuardTest` (`AgendaBuddy.IntegrationTests/Audit/EventStoreWriteGuardTest.cs`) asserts the
literal substring `eventStore.SaveAsync(` appears **anywhere in the whole handler file** — not that every
code path (each `if`/`return` branch) calls it. This is weaker than "fails when the EventStore write is
removed from the command path" read literally (singular path implied per branch), and the gap is not
theoretical: it already missed the exact defect this same session found by hand —
`UpdateServicesFromProviderCommandHandler.cs:20`'s not-found branch writes no audit event at all
(`agenda-buddy-f49`), yet the file still contains `eventStore.SaveAsync(` twice elsewhere (lines 42, 54), so
the guard passes on it. **Corrected claim:** the guard proves the audit-writing call site is not deleted from
the file entirely — a real, permanent, convention-based regression net (new handlers are covered
automatically, no edit needed) — but it does **not** prove every branch of every handler calls it. Per-branch
coverage would need either a bigger, purpose-built static-analysis check or exhaustive per-branch integration
tests (the actual AC-7 tests already partially do this per-service, per-branch, where written) — judged
disproportionate for a "permanent guard" task under YAGNI, logged as tech debt rather than built now. The two
real per-branch gaps this session found (`agenda-buddy-f49`, and `UpdateCustomerCommandHandler`'s wrong audit
`Type`, `agenda-buddy-id4`) were caught by T13's own manual per-handler reading, not by this guard.
